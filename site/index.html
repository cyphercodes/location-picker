Get started

Copy, paste, done

One script tag defines <location-picker>. Keep the @3 in the URL: it pins the major version.

e.detail also has lat, lng, source and, with reverse-geocode, the address.

Submits location=48.85837,2.294481. For separate fields add lat-name="lat" lng-name="lng"; required, reset and back/forward restore work like a native input.

Your own inputs seed the picker and submit themselves. Without JavaScript they stay visible and editable; jQuery, Livewire and Alpine see native events on them.

React, Vue, Angular, Svelte, Solid and Preact recipes: docs/frameworks.md. The class without the element: import { LocationPicker } from 'location-picker/core'.

Why it fits forms

One point, done properly

A real form control

Submits name=lat,lng, separate lat/lng fields or your own hidden inputs. required, reset and back/forward restore behave like an input.

No key, no prompt

OpenStreetMap tiles and Photon search by default. The location permission is asked only when someone taps “Use my location”.

Search or paste anything

Type an address, or paste 48.8584, 2.2945, DMS, a geo: URI or a Google, OpenStreetMap or Apple Maps link.

Keyboard and screen reader

Arrow keys pan, +/− zoom, Enter picks. Controls are 44 px targets and every pick is announced politely.

Any framework

Plain HTML, React 19, Vue 3, Angular, Svelte 5, Solid and Preact through standard events; Laravel, Django and Rails through bound inputs.

Ready for AI agents

llms.txt, an Agent Skill in the npm package, typed errors that name the fix, and opt-in WebMCP tools.
